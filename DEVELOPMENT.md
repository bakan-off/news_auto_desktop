# Справочник разработчика — КМЦБС Новости

Этот документ — исчерпывающее описание проекта для человека **или ИИ-агента**, который
приступает к доработке без какого-либо контекста. Прочитайте его целиком перед
изменением кода; в конце — история всех найденных багов и извлечённых уроков
(раздел «Post-mortem») — это самое ценное.

---

## 1. Что это за программа

Desktop-приложение для Windows, которым сотрудники библиотек МКУК «КМЦБС»
(Кондинское МЦБС, ХМАО) отправляют новости для публикации.

**Сценарий работы сотрудника:**

1. Запускает exe. При первом входе видит один экран: почта получателя
   новостей (предзаполнена) и пароль облачного аккаунта (выдаёт
   администратор лично; не знает — пишет администратору на почту, адрес
   подсказан на экране). Пароль проверяется реальным SMTP-логином и
   запоминается на машине; повторные запуски открывают программу сразу.
2. Заполняет форму: филиал (по умолчанию «Не указывать» — программа
   ничего не подставляет сама; осознанный выбор запоминается),
   свою рабочую почту (автор новости), название, описание, возрастной
   ценз, хештеги, прикрепляет фото/файлы, отмечает соцсети.
   Новая почта подтверждается кодом из письма — прямо в форме, один раз
   до смены почты (v1.6.0): администратор отвечает автору на настоящий
   адрес (Reply-To в письме).
3. Жмёт «Отправить». Файлы едут в облако Mail.ru (WebDAV), администратору
   уходит HTML-письмо со ссылкой на папку облака и кнопками соцсетей.
4. Администратор вручную публикует новость на сайт и в соцсети.

**Важно:** программа НЕ публикует в соцсети сама — она готовит материал
для человека-администратора. Прямая публикация (VK API) — в планах.

Роли: `сотрудник` (отправляет) и `администратор` (получает письма,
в его почту настроен `admin_email`).

## 2. Стек и структура репозитория

- Python 3.13, customtkinter 5.2.2 (UI), webdavclient3 (облако), windnd
  (drag&drop), Pillow (миниатюры), PyInstaller (сборка exe).
- Тесты: pytest; линтер: ruff. GUI-фреймворк Tkinter через customtkinter.

```
news_auto_desktop/                # публичный репозиторий: исходники + релизы
├── main.py        # весь UI + логика приложения (~1740 строк)
├── core.py        # чистая логика без UI: валидация, WebDAV-урлы, секреты,
│                  # письмо, config.json, проверка обновлений (~720 строк)
├── theme.py       # палитры тёмной/светлой темы
├── conftest.py    # доступ к модулям из тестов
├── tests/         # 97 тестов pytest
├── build.ps1      # сборка exe + чистый zip (см. раздел 7)
├── publish_dist.ps1  # публикация релиза в этот же репозиторий (раздел 6.2)
├── app.ico        # иконка приложения
└── requirements*.txt
```

**Почему один публичный репозиторий:** секретов в коде нет (пароль вводит
сотрудник, хранит Credential Manager), публиковать нечего. Релизы (zip) и
проверка обновлений живут там же, где исходники. История репозитория
начата заново с чистого коммита v1.4.0 — старая история содержала пароль
и не должна была стать публичной (см. раздел 9).

## 4. Модули и их устройство

### 4.1 `core.py` — логика без UI (тестируется pytest)

Ключевые константы: `APP_VERSION` (поднимается при релизе!), `GITHUB_REPO`
(основной публичный репо `bakan-off/news_auto_desktop`), лимиты
(`MAX_TITLE_LEN=100`, `MAX_DESC_LEN=5000`, `MAX_FILES=10`,
`ATTACH_WARN_MB=50`, `ATTACH_LIMIT_MB=200`, `HISTORY_LIMIT=100`).

Основное:

| Функция | Что делает |
|---|---|
| `validate_submission()` | обязательные поля, длины, вес вложений |
| `make_cloud_folder()` | имя папки новости `ДДММГГГГ-ЧЧММСС-hex` |
| `unique_remote_names()` | имена файлов без коллизий (`отчёт(1).pdf`) |
| `public_file_url()` / `cloud_folder_link()` | веб-ссылки на облако Mail.ru |
| `build_report_html()` | HTML-письмо админу; экранирует всё пользовательское, `\n`→`<br>`, неактивные соцсети — красные перечёркнутые плашки |
| `header_safe()` | сворачивает переносы/табы для темы письма |
| `with_retries()` | повторы сетевых операций (пауза растёт: 2с, 4с…) |
| `fetch_latest_version()` | теги GitHub + ETag-кэш (раздел 6) |
| `parse_version()` / `is_newer_version()` | сравнение `vX.Y.Z` по компонентам |
| `store_secret()` / `load_secret()` / `delete_secret()` | пароли в Windows Credential Manager через ctypes (advapi32 `CredWriteW`/`CredReadW`), target `КМЦБС_Новости/<ключ>`, blob UTF-16-LE |
| `migrate_secrets_to_cred_manager()` | разовый перенос паролей из config.json в диспетчер |
| `is_auth_error()` | ошибка авторизации SMTP/WebDAV (пароль не подошёл) — по ней предлагают ввести пароль заново, а не «повторить» |
| `is_same_email()` | сравнение адресов без регистра/пробелов — смена почты сбрасывает подтверждение |
| `generate_verification_code()` | 6-значный код подтверждения (`secrets`, не `random`) |
| `build_verification_email_html()` | письмо с кодом подтверждения почты автора |
| `news_subject()` | тема письма админу: без филиала скобка не добавляется |
| `BRANCH_NOT_SPECIFIED` | «Не указывать» — филиал по умолчанию, программа не выбирает филиал за сотрудника |
| `load_settings()` / `save_settings()` | config.json; запись атомарная (tmp + `os.replace`), при повреждении файла — бэкап `config.json.corrupt-<время>` |

### 4.2 `theme.py` — темы

Два словаря `DARK` / `LIGHT` с одинаковыми ключами. `theme.current()` возвращает
палитру по фактическому `ctk.get_appearance_mode()`. Режимы: `"dark"` | `"light"`
(«Системная» удалена в v1.2.0; старые конфиги с `"system"` не ломаются).

**Железное правило: в `main.py` запрещены захардкоженные hex-цвета** — только
ключи палитры (`self.palette["..."]`). Нарушение = невидимый текст/элементы
после переключения темы (уже случалось, см. post-mortem).

### 4.3 `main.py` — приложение

Классы:

- `CustomMessagebox` — модальное инфо/ошибка (`grab_set` обёрнут в try — на
  скрытом окне кидает TclError).
- `CustomYesNoBox` — вопрос да/нет, `get_result()` ждёт закрытия.
- `LoginWindow` — единственный экран входа (v1.5.0): почта получателя
  (предзаполнена из `admin_email`) + пароль. Пароль проверяется реальным
  SMTP-логином в фоновом потоке (`_check_credentials`); успех → оба ключа
  в Credential Manager, вход. Неверный пароль — инлайн-ошибка под полем
  (модальных окон нет), после `LOGIN_MAX_ATTEMPTS` неудач — пауза
  `LOGIN_LOCKOUT_SEC` (перебор мог бы надолго заблокировать общий
  аккаунт на mail.ru). Коды подтверждения почты удалены в v1.5.0:
  без секретов в exe они дублировали сам пароль; mailto-запрос пароля
  удалён там же — не работал без почтовой программы и плодил окна.
- `NewsApp(ctk.CTk)` — главное окно: боковая навигация (4 страницы:
  Отправить / Черновики / История / Настройки), всё содержимое строится
  в `main_container` внутри `CTkScrollableFrame`; смена страницы = полный
  `clear_main_container()` + отрисовка заново.

Ключевые методы `NewsApp`:

| Метод | Назначение |
|---|---|
| `load_settings()` / `save_settings()` | config.json + миграция секретов (пароли при сохранении уходят в Credential Manager, в файле затираются) |
| `show_send_frame()` и др. | страницы; раскладка grid (row-номера фиксированы — проверяйте при вставке новых блоков) |
| `_collect_payload()` | снимок формы (словарь) — фоновый поток работает ТОЛЬКО с ним, не с виджетами |
| `submit_news()` | валидация → подсветка пустых обязательных полей → гейт «почта подтверждена?» → подтверждение «без файлов?» → поток `process_sending` |
| `_email_*` / `send_author_code()` / `_check_author_code()` | подтверждение почты автора в форме: код на почту, ввод и проверка инлайн, пауза между отправками, TTL/попытки из core |
| `process_sending(payload)` | WebDAV mkdir/upload с ретраями → SMTP-письмо → запись в историю |
| `preview_report()` | то же письмо в браузере (та же `build_report_html`, без расхождений) |
| `check_for_updates()` | проверка версии ТОЛЬКО по кнопке в настройках (автозапуска нет с v1.6.2), с защитой от повторных нажатий |
| `_poll_ui_queue()` / `ui_post(fn)` | НИТЬ БЕЗОПАСНОСТИ UI — см. раздел 5 |
| `change_theme(label)` | сохранение режима + перерисовка страницы |
| `on_close_app()` | автосохранение черновика, блокировка закрытия во время отправки |

### 4.4 Где живут данные

Всё локально, рядом с exe (`core.app_dir()` — папка, где лежит программа;
в dev-режиме — корень репозитория):

| Файл | Что внутри |
|---|---|
| `config.json` | настройки + черновики + история (см. ключи ниже); **личный, в рассылку не попадает** |
| `.update_cache.json` | ETag-кэш проверки обновлений; не личный, но в архив тоже не кладём |
| `app.log` | лог (ротация 1 МБ × 3); **личный** |

Ключи config.json: `webdav_url/webdav_login/webdav_password`,
`smtp_server/smtp_port/smtp_user/smtp_password/admin_email` (это `DEFAULTS`
в `main.py`; значения паролей — пустые строки, секретов в коде нет),
`appearance_mode`, `hashtags`, `verified_email` (ПОДТВЕРЖДЁННАЯ почта
автора: подставляется в форму; меняется только успешным вводом кода,
не редактированием поля), `last_branch` (осознанный выбор сотрудника;
по умолчанию «Не указывать»), `drafts`, `history`. Пароль при работе хранится в Windows
Credential Manager (записи `КМЦБС_Новости/webdav_password` и
`.../smtp_password`), в config.json пустые строки. Пароль вводится один раз
на экране входа (один пароль на оба ключа — аккаунт облака и почты общий)
и никогда не попадает в код.

Черновик: словарь с полями формы + `date`. История: то же + `file_links`
(ссылки облака), `local_files` (пути, для «Повторить»), `folder`; максимум
100 записей (`HISTORY_LIMIT`).

## 5. Многопоточность и UI — КРИТИЧЕСКИЕ ПРАВИЛА

Tkinter не потокобезопасен. **Любое обращение к виджетам из фонового потока
(в том числе `self.after(...)`) может обрушить процесс** с `Tcl_AsyncDelete`
— мгновенно и без следов в логе. Так уже падало (v1.1.0).

Правильный паттерн (реализован, пользуйтесь им):

```python
# из фонового потока:
self.ui_post(lambda: self.progress_label.configure(text="..."))
```

`ui_post` кладёт замыкание в `queue.Queue`; главный поток выгребает очередь
каждые 80 мс в `_poll_ui_queue()` и исполняет. Диагностика: переопределённый
`report_callback_exception` (ошибки колбэков Tk) и `sys.excepthook` (крэши)
пишут всё в `app.log` — в оконной сборке exe stderr не существует, без этого
причины вылетов невидимы.

Исключения в фоновых потоках: оборачивайте в try/except и сообщайте через
`ui_post` + `CustomMessagebox`, как в `process_sending`.

## 6. Проверка обновлений и релизы

### 6.1 Как устроена проверка

`core.fetch_latest_version()` → GET `https://github.com/bakan-off/news_auto_desktop/tags.atom`
→ максимальный `vX.Y.Z` из ленты. Сравнение с `APP_VERSION` → диалог «Доступно
обновление» со ссылкой на страницу релизов.

Особенности:

- **Лента Atom, а не api.github.com.** Анонимный API GitHub ограничен
  60 запросами в час НА IP-АДРЕС, офисы сидят за общим NAT и делят лимит
  со всем офисом — он почти всегда исчерпан (`HTTP 403 rate limit`),
  проверка вечно говорила «не удалось». Веб-лента `tags.atom` отдаётся
  сайтом GitHub и таким лимитом не обладает.
- **ETag-кэш** (`.update_cache.json` рядом с программой): повторные проверки
  уходят с `If-None-Match`, сервер отвечает `304 Not Modified` — запрос
  фактически бесплатный. TTL кэша 7 дней.
- При 403/сети и свежем кэше (7 дней) отдаётся кэш; кэш протух + сети нет →
  `None` → «не удалось проверить».
- User-Agent только ASCII (`KMCBS-News-Update-Check`): кириллица в заголовке
  ломала запрос целиком.
- Кнопка «Проверить обновления» блокируется на время проверки (`_update_check_busy`):
  иначе каждый клик рождал поток и окно результата (стопка окон).
- Автоматических проверок НЕТ (v1.6.2): только кнопка «Проверить обновления»
  в настройках — по требованию заказчика. Ошибки сети показываются.

### 6.2 Процесс выпуска версии (полный, по шагам)

1. Внести изменения, прогнать `pytest` + `ruff`.
2. Поднять `APP_VERSION` в `core.py`, закоммитить.
3. Собрать: `pwsh -File build.ps1` (см. раздел 7) → `dist\КМЦБС-Новости\`
   (локальная сборка с вашим config.json) и `dist\КМЦБС-Новости.zip` (чистый).
4. Пометить исходники: `git tag v1.4.0 && git push origin main v1.4.0`.
5. Опубликовать релиз: `pwsh -File publish_dist.ps1` — создаст Release
   `v1.4.0` в этом же репозитории и прикрепит zip как
   `KMCBS-News-1.4.0.zip` (имя только ASCII!). Опционально `-Notes "текст"`.
6. Проверить руками: страница `github.com/bakan-off/news_auto_desktop/releases`
   открывается в режиме инкогнито, архив скачивается.

После этого у всех пользователей при запуске/проверке появится предложение
обновиться.

### 6.3 Обновление на машине пользователя

Сотрудник скачивает новый zip и распаковывает поверх старой папки.
`config.json` (почта, черновики, история) живёт рядом с exe и переживает
обновление.

## 7. Сборка (build.ps1)

`pwsh -File build.ps1` делает всё сам:

1. Сохраняет ваш `config.json`/`app.log` из папки сборки во временный каталог
   (PyInstaller `-y` стирает её).
2. Генерирует ресурс версии из `APP_VERSION` (`--version-file`): издатель/
   название/версия в свойствах exe — Windows показывает их в диалогах вместо
   «безымянного файла». Файл ресурса обязан быть UTF-8 БЕЗ BOM — PyInstaller
   не разбирает текст с BOM.
3. PyInstaller **onedir** (не onefile!): `--noconsole --collect-data customtkinter
   --version-file <сгенерированный> --icon app.ico --add-data "app.ico;."
   --name КМЦБС-Новости main.py`.
4. Возвращает ваши config.json/app.log в локальную папку сборки.
5. Пакует чистый zip через staging-каталог: **без** `config.json`, `app.log`,
   `.update_cache.json`.

Релиз мимо `dist\` (локальная установка в `dist\` нужна для проверки
обновления из репозитория): `pwsh -File build.ps1 -OutDir <пустая папка>` —
сборка и zip уйдут туда, `dist\` не тронется.

Грабли PowerShell, уже учтённые в скрипте (не «чините» обратно):

- Файл обязан быть в UTF-8 **с BOM**, иначе Windows PowerShell читает
  кириллицу как cp1251-мусор и падает на синтаксисе.
- `Join-Path` принимает только 2 аргумента (не три).
- `$ErrorActionPreference="Stop"` + stderr внешней команды (PyInstaller) при
  редиректе = терминальная ошибка; вокруг вызова политика ослабляется,
  вывод идёт в `build_pyinstaller.log`.
- onefile не использовать: VCRUNTIME140.dll распаковывается во временную
  папку с Permission denied.

## 8. Тестирование и GUI-пробы

Юнит-тесты (80 шт.) покрывают core.py и theme.py целиком. Запуск:
`python -m pytest -q` из корня. При правке core-функции сначала пишем тест.

**GUI-пробы** — для того, что юнит-тестами не проверить (раскладка, темы,
диалоги). Паттерн (см. `%TEMP%\nad_*.py` из истории сессий):

```python
sys.path.insert(0, r"D:\Harness\news_auto_desktop")
tmpdir = tempfile.mkdtemp()
core.app_dir = lambda: tmpdir          # данные — во временную папку
import main
app = main.NewsApp(); app.withdraw()   # без видимого окна
# отключить фоновые проверки и подменить диалоги:
main.NewsApp.check_for_updates = lambda self: None
class FakeBox:
    def __init__(self, *a, **k): ...   # собрать вызовы в список
main.CustomMessagebox = FakeBox
# ...вызвать методы, проверить состояние, app.update() для отрисовки...
print(f"KEY={value}")                  # KEY=value в конец
print("ALL_OK" if ok else "SOME_FAILED")
```

Нюансы проб: `app.protocol("WM_DELETE_WINDOW", app.destroy)` перед destroy;
диалоги `CustomYesNoBox.get_result()` блокируют — подменяйте класс целиком;
не доверяйте первому прогону, отличайте баг пробы от бага приложения.
`after()` из фонового потока работает только при живом `mainloop()`
(`RuntimeError: main thread is not in main loop` под `app.update()`):
если проба ждёт результат потока — ждите через `app.after(ms, app.quit);
app.mainloop()`, а не циклом `update()`.
Credential Manager в пробах обязательно замокать
(`core.load_secret`/`store_secret`/`delete_secret`), иначе проба читает
секреты реальной машины. В песочнице DSH pytest-фикстура `tmp_path` может
падать с PermissionError — используйте `tempfile.mkdtemp`.

## 9. Известные компромиссы и риски

1. **До v1.4.0 пароль облака/почты был зашит в `DEFAULTS`** и попадал в
   каждый exe (из бинарника извлекается pyinstxtractor'ом за минуты) и в
   историю Git. С v1.4.0 секретов в коде и сборках нет: пароль вводится
   сотрудником на экране настройки и живёт в Credential Manager. Но копии
   старых версий (exe на машинах, скачанные архивы v1.3.2 и младше)
   по-прежнему содержат рабочий пароль; владелец принял решение пароль
   НЕ менять — остаточный риск осознан и задокументирован. Полное
   закрытие утечки = смена пароля аккаунта в mail.ru (решение и действие
   только владельца; после неё старые копии мертвеют, а программа
   предложит ввести новый пароль через экран настройки — ошибки
   авторизации распознаются).
2. Режим администратора в настройках — просто галочка без пароля
   (осознанное решение).
3. Проверка обновлений — по ленте тегов GitHub (лимитов API нет);
   остаточная зависимость от доступности github.com.
4. Старые установки (до v1.3.2 включительно) проверяют обновления в
   удалённом репозитории `-dist` — они узнают о новых версиях только из
   рассылки администратора (v1.4.0 была разослана письмом).
5. **Недостижимые коммиты старой истории ещё отдаются GitHub по прямой
   ссылке SHA** (проверено: `…/commit/<sha>` → 200 после переписывания
   истории). Их не видно в ветках, тегах, поиске и логах — ссылку нужно
   знать точно (40 hex-символов). GitHub вычищает такие объекты при
   внутренней сборке мусора; ускорить — только через GitHub Support.
   Окончательное решение — смена пароля аккаунта (владелец решил пока
   не менять).

## 12. Post-mortem: все уроки проекта

| Симптом | Причина | Правило на будущее |
|---|---|---|
| Вылет приложения при навигации по меню | фоновый поток звал `self.after()` (Tcl_AsyncDelete) | UI из потока — только через `ui_post` |
| «Почему вылетело» — в app.log пусто | в оконном exe нет stderr | `report_callback_exception` + `sys.excepthook` пишут в лог |
| Проверка обновлений молча не работала | кириллица в User-Agent (`latin-1` codec) | HTTP-заголовки только ASCII |
| Кнопка обновлений наезжала на переключатель темы | два блока в одной grid-строке | при вставке блоков проверяйте row-номера |
| Светлая тема: «шрифты не видно» | у прозрачных кнопок не задан `text_color`, CTk подставляет белый из тёмного дефолта | все цвета — из палитры, включая text_color прозрачных кнопок |
| Стопка окон «не удалось проверить» | каждый клик = свой поток и своё окно; плюс rate limit GitHub (60/час с IP) | блокировать кнопку на время проверки; ETag-кэш |
| «Не удалось проверить обновления» упорно у пользователя | анонимный API GitHub — лимит 60/час НА IP, офис за общим NAT делит его со всеми | проверки через веб-ленту `tags.atom`, не через `api.github.com` |
| Стих «столбиком» приходил сплошным текстом | `\n` не превращался в `<br>` | esc(desc) → `<br>` с нормализацией `\r\n` |
| Большая пустота между блоками при пустом списке файлов | пустой CTkFrame держит дефолтные 200px в grid | пустой контейнер — `grid_forget()` |
| grab_set кидал TclError | окно ещё не отображено | `try/except` вокруг grab_set |
| Запуск «в обход» окна входа: окно не появлялось | `deiconify/zoomed` до старта mainloop терялись | вход через `after(50, on_login_success)` |
| «Открыть мою почту» не работала, запрос пароля плодил модальные окна | mailto требует настроенного почтового клиента (на библиотечных ПК его нет); каждое действие обёртывалось в своё окно | не строить флоу на mailto; ошибки и статусы — инлайн на экране; «не знаю пароль» — строка с адресом, а не мастер писем |
| Новости приписывались чужому филиалу | филиал по умолчанию = первый элемент списка, сотрудник не замечал подмену | дефолты, приписывающие авторство/принадлежность, запрещены: «Не указывать» + запоминание только осознанного выбора |
| Синее предупреждение SmartScreen на скачанный exe («раньше не было») | неподписанный exe + метка «скачано из интернета» (MOTW); локальные сборки метки не имеют, поэтому не предупреждались | ресурс версии в exe + инструкция «Разблокировать» (README и текст релиза); полностью решает только платная цифровая подпись |
| build.ps1 падал на кириллице | UTF-8 без BOM читается как cp1251 | BOM обязателен |
| build.ps1 падал на выводе PyInstaller | Stop-политика + stderr нативной команды | ослаблять EAP вокруг, вывод в лог-файл |
| Архив распаковывался в `nad_clean_dist` | staging-каталог пакуется как корень | staging → внутри папка с именем приложения |
| Конфиг возвращался из бэкапа как `nad_keep_config.json` | `Copy-Item -PassThru` вернул путь бэкапа, восстанавливали по нему | стейджинг с исходными именами файлов |
| Ассет релиза на GitHub назывался `-.zip` | кириллица в имени актива искажается через API | имена ассетов — только ASCII |
| onefile-exe не запускался | VCRUNTIME140.dll распаковка denied | только onedir |
| pip вис в песочнице | сетевой слой | офлайн-колёса через urllib |
| В zip попал заполненный config.json | паковали папку сборки как есть | staging + явные удаления личных файлов |
| Пароль из exe извлекался инструментами за минуты | секрет в DEFAULTS = секрет в каждом бинарнике и в истории Git | пароль не хранится в коде: вводится пользователем, живёт в Credential Manager; историю с секретами не публиковать — начинать заново |

## 13. Правила проекта (сводка)

1. В коде нет и не должно быть секретов (паролей, токенов). Пароль
   облачного аккаунта выдаёт администратор лично и вводит сотрудник;
   возвращение пароля в `DEFAULTS`/код — ошибка.
2. Все цвета — из `theme.py`; никаких hex в `main.py`.
3. UI из фоновых потоков — только `ui_post`.
4. Новая логика core.py — сначала тест, потом код.
5. В дистрибутив (zip) не попадают: `config.json`, `app.log`,
   `.update_cache.json`.
6. Имена файлов рассылок/ассетов — ASCII.
7. Перед релизом: pytest + ruff + GUI-проба + смок-тест exe
   + байт-скан сборки на отсутствие пароля.
8. Релиз: `APP_VERSION` → коммит → `build.ps1` → тег → `publish_dist.ps1`
   (в этот же репозиторий).
